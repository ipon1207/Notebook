## アプリケーションのターゲット

1. **SQL の初学者がメインのターゲット**
2. **次に、SQL の学習でつまずいた経験のある人がサブターゲット**

## `sqlSimulator.ts`の改善内容

- ロジックの切り分け: 今後の拡張や保守を容易にするため、SQL の解析、実行、結果の生成などのロジックをモジュール化する

## プロダクトとして確立

- ユーザーフィードバックの収集: 初期ユーザーからのフィードバックを基に、UI/UX の改善や新機能の追加を検討する
- ドキュメントの整備: ユーザーガイドや FAQ を作成し、ユーザーが自己解決できるようにする
- SEO 対策: 検索エンジンでの可視性を高め、より多くのユーザーにリーチするための施策を講じる（それに応じた技術スタックを利用）

## 現状の技術スタック

- フロントエンド: Next.js
- バックエンド: Next.js API Routes（やめたい）
- スタイリング: Tailwind CSS
- データベース: なし（データベースで管理したい）
- インフラ: Vercel

## 「研究特化」と感じている課題点

研究に特化したというよりは、研究を早く終わらせるためにコア機能の実装のみを急ぎ、UI/UX や拡張性、保守性を後回しにしている点が課題です。

## 今後の方向性（価値）

- 価値: 環境構築不要で手軽に SQL を学べるプラットフォームの提供と視覚的なフィードバックによる理解促進

## プロジェクトについて

- ほとんどが AI に生成させたコードで構成されているため、コードの品質や一貫性に課題がある上、開発者自身が SQL の専門家ではないため、専門的な知識が不足している点が課題
- ドキュメントやテストコードが不十分であり、将来的な保守や拡張が難しい状況
- ユーザーインターフェースが直感的でないため、ユーザーエクスペリエンスの向上が求められる
- データベースを利用しない設計のせいで、問題データを管理する静的ファイルの肥大化や更新の手間が発生している点が課題
- SQL の全機能を網羅していないため、学習者が特定の SQL 機能を試せない場合がある点が課題
- Next.js API Routes をバックエンドに使用しているが、スケーラビリティやパフォーマンスの面で制約がある点が課題
- 開発者自身が Next.js や Tailwind CSS に不慣れ
