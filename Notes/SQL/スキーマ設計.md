## どんなデータを管理すべきか？

- ユーザー（名前、メールアドレス、パスワード）
- 問題（タイトル、内容、難易度、カテゴリー）
- 模範解答（問題 ID、解答 SQL、解説）
- ユーザーの学習進捗

## テーブル構成案

1. profiles（ユーザー）テーブル
   - user_id
   - email
   - ~~password~~
   - **username**
   - created_at
2. problems（問題）テーブル
   - problem_id
   - title
   - content
   - init_sql
   - difficulty
   - category
3. answers（模範解答）テーブル
   - answer_id
   - problem_id
   - answer_sql
   - explanation
4. user_progress（学習進捗）テーブル
   - progress_id
   - user_id
   - problem_id
   - status
   - user_submitted_sql
   - solved_at

## ER 図のイメージ（あくまでイメージなので、確定ではない）

```mermaid
erDiagram
    profiles {
        UUID id PK "auth.usersのIDと紐付け"
        STRING email "表示用"
        STRING username "表示名"
        DATETIME updated_at
    }

    categories {
        INT id PK
        STRING title "例: SELECT基礎"
        STRING slug "例: select-basics"
        INT order_index "表示順序"
    }

    problems {
        UUID id PK
        INT category_id FK
        STRING title
        TEXT content
        TEXT init_sql "初期データ作成SQL"
        TEXT answer_sql "模範解答SQL"
        TEXT explanation "解説Markdown"
        ENUM difficulty "easy, medium, hard"
    }

    user_progress {
        UUID id PK
        UUID user_id FK
        UUID problem_id FK
        ENUM status "solved, attempted"
        TEXT user_submitted_sql
        DATETIME last_attempt_at
    }

    profiles ||--o{ user_progress : has
    categories ||--o{ problems : contains
    problems ||--o{ user_progress : tracked_in
```
